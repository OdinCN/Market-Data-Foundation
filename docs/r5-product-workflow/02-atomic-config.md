# 02 能力与凭据的一次保存

本实现仍是候选代码，验证只用临时合成存储。没有配置真实运行环境、验证来源认证或启动采集。

同一个管理弹窗的能力配置和来源配置共用 `PUT /api/r5/packages/{package_id}`。`keep` 复用受信 Host 的现有凭据状态与加载入口；`replace` 使用仅写入的 `credential_value`。目前只支持 BLS、BEA，且只能替换本次所选能力需要的来源。环境、存储路径与凭据引用都由 Host 确定，浏览器不能传入。

`PackageHost(credential_replace_enabled=False)` 默认拒绝替换。Host 明确装配后才公布 `replace_supported`；保存资格仍由原有权限判定提供。默认应用未装配时继续返回明确不可用，不创建空配置或猜测运行能力。

## 生效边界

`LocalPackageStore` 在同一把独占锁内核验原修订。新凭据先写入私有目录中的不可变文件，文件和目录都确认持久化后，才用一次 `packages.json` 原子替换发布新能力集合和凭据引用。快照不含密钥值，公开 DTO 也不含凭据引用。当前实现要求单主机 POSIX、同一可加锁目录及具备原子替换语义的本地文件系统；不声称支持跨主机分布式保存。

- CAS 冲突在准备凭据前拒绝，旧配置保持。
- 凭据准备或快照替换前失败，配置效果为 `NONE`。可能留下未被任何配置引用的私有准备文件；该文件不会被加载。不自动删除旧凭据或进行垃圾回收。
- 快照替换后持久化确认或响应投影失败，返回 `config_commit_outcome_unknown`、`effect=UNKNOWN`；客户端必须重读，不自动重放。
- 停用能力保留所有已保存的凭据引用及历史。重新启用可复用；来源认证仍是 `unknown`，不能由“已配置”推断来源准入。

## Host 与 Worker 读取

`PackageHost.load_credential(package_id, source_id, record=...)` 是服务端入口，不是 HTTP 接口。读取同一个 `ConfigRecord` 可让能力判断和凭据解析使用同一修订；凭据不可变，既有在途操作可以继续解析原记录。未提供记录时读取当前环境的当前快照。不同环境或包的记录被拒绝。

没有已发布的新引用时，可调用 Host 提供的 `credential_loader(environment_id, package_id, source_id)`，复用已有受信配置；不复制或更改旧配置。存在新引用时只解析该引用，缺失、损坏、符号链接或非私有权限均拒绝，不能静默回退到旧 Key。凭据文件要求当前服务用户所有、私有目录和私有普通文件。

本轮没有把真实 BLS/BEA 加载器、WebUI 运行 Host 或 Worker 接到该入口；后续装配必须明确使用相同存储和环境，不沿用开发机硬编码路径。D02 来源资格、权限、具名绑定与范围判断继续独立存在；本地合格读取不依赖凭据可用。

## 前端草稿

密码输入仅属于当前弹窗草稿。能力切换不访问来源；来源退出当前选择时清除其待替换草稿。取消、关闭和重新读取均丢弃输入。发出请求后清除输入；跨页面只保留非敏感的启用集合、原修订、待核对来源名称和传输状态。

保存被明确拒绝时，保留空白的替换意图，要求重新输入或明确取消该来源的替换，不能下一次悄悄只保存能力集合。丢失回执时重读只显示当前配置状态，不声称证明新 Key 与刚才输入相同，也不重发它。来源认证、接口测试、采集及持久化发布不由本次保存隐式触发。
